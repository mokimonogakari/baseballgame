> 調査日 2026-11-08。既存ノート（`docs/PAWAPURO-RESEARCH.md`、`docs/research/PAWAPURO-MATCH.md` / `-SYSTEMS.md` / `-FIELDING.md` / `-BATTING-PITCHING.md`）で扱った内容は**繰り返さず**、参照番号だけ書く（例: MATCH §4-6、MATCH 提案 #21）。
> 表記: **【事実】** は出典つき、**【推測】** は根拠を書いた推定、**【提案】** は本作への実装案。確かめられなかったものは **未確認**。

## 0. 要点（先に結論）

1. **パワプロらしさは「1 つひとつの結果に、人が反応する」ことで出る。** 初代（1994）から、空振りで転ぶ・死球で泣き顔・際どい球を見送って振り返る・足元をならす、といった**打者の小さな反応**が売りだった【事実: GAME Watch】。本作は打撃・投球のモーションは細かいが、**結果のあとに誰も反応しない**（打者・投手・審判・ベンチ）。ここが最大の差。
2. **審判が画面にいない。** 声（VOICEVOX）はあるが姿とジェスチャーがない。実際の審判のシグナルは単純な形で決まっており（ストライク＝拳を斜め前に、アウト＝拳を頭上、セーフ＝両腕を水平、ファウル＝両手をハの字、本塁打＝人差し指で腕を回す）【事実: Wikipedia「審判員 (野球)」】、ちびキャラ 1 体＋CSS で作れる。
3. **試合の「節目」の演出が 1 種類しかない。** いまは攻守交代・試合開始・試合終了・投手交代がすべて同じ `showOverlay`（大文字＋小文字）。サヨナラも普通の GAME SET と同じ。節目ごとに**見せる情報**（スコアボード、交代投手の紹介、勝者の喜び）を変えるだけで試合らしくなる。
4. **ヒーローの選び方**は「決勝打」を重く見るのが野球の習慣で、パワプロもその傾向（不満の声も含めて）【事実: 知恵袋（MATCH §4-6 で既出）】。本作の MVP は合計点（安打＋本塁打×2＋打点×1.5 …）で、決勝打を考えない。
5. **短時間で遊ぶ工夫**として、公式は「おいしいところだけプレイ」（LIVE シナリオのピックアップ）、「タイムメニューからいつでもリトライ」、「サクッと育成」を入れている【事実: 2020 開発タイムライン、2024-2025 モード】。ブラウザ向きなのは**場面から始める 1 打席〜1 イニングの挑戦**と**すぐリトライ**。
6. 秒数の公式値はほぼ公開されていない（**未確認**）。かわりに現実の NPB の規定（攻守交代 2 分 15 秒以内、イニング間の投手交代 2 分 45 秒以内、走者なしの投球間隔 15 秒以内）【事実: NPB】を「ゲームはこれを何十分の一に縮めている」基準として使い、本作の目標秒数を §6 で決める。

### 1-3. 推測（遊んだ人なら分かる「型」を、根拠つきで書く）

- 【推測】パワプロ系の試合は「**節目の演出は数秒・ボタンで飛ばせる・繰り返し見る演出ほど短い**」で設計されている。根拠: 紹介デモは「スキップせずに見てほしい」とわざわざ言うほど飛ばされる前提（2016）、デモ尺 10〜15 秒（2020）、テンポのために出番を減らした（2020 タイムライン第1回「さらに試合のテンポを上げるために出番を減らして」）、大会規定で演出を個別に ON/OFF（MATCH §6）。
- 【推測】実野球の 2 分 15 秒の攻守交代を、ゲームは 1〜3 秒程度に縮めている。根拠: 1 試合 9 回の所要時間が 30〜60 分程度（MATCH §3-4）で、18 回の攻守交代に長い時間を割けない。

### 2-3. 推測

- 【推測】パワプロの「かわいさ」は、**2〜3 頭身の体が大きく反応する**ところにある（転ぶ・泣き顔・振り返る）。体の部位が少ない分、**ポーズの変化を大きく・短く**して読ませている。本作の CSS ちびキャラ（`chibiHTML`、部位: 頭・帽子・目・頬・口・体・腕・脚）でも、**目と口の形の差し替え＋体の傾き＋小さなジャンプ**で同じ方向の表現ができる。

## 3. 画面・UI・サウンドの手触り

### 3-1. 事実

- 能力表示の並び（弾道・ミート・パワー・走力・肩力・守備力・捕球）、ランク文字の色分け、特殊能力の地色（金・青・赤）、調子の顔マーク 5 色は **MATCH §1-4 / §5 で既出**。特殊能力の色の意味（金＝超特殊能力、青＝プラス、赤＝マイナス、緑＝CPU の性格）は **SYSTEMS §2-1 で既出**。
- ミートカーソルが消える設定（「フレッシュ設定」、打撃システム「フルダケ」）がある＝**カーソル表示も選択肢**【事実: Switch 版 FAQ https://www.konami.com/pawa/switch_support/faq/pawa_switch/jp/ja/switch/item?no=16】。
- BGM は「**環境音などの SE が活きるように、音に隙間を与える**」アレンジ【事実: 2020 開発タイムライン第3回 https://www.konami.com/pawa/2020/development/timeline_3】。
- 2018 は「アクションボイス」（遠くの選手の「おりゃ！」）を追加。審判の声も**位置に合わせて鳴る**【事実: 2018 前夜祭 試合編】。
- 2018 は時間帯で光が変わる（夕方のまぶしさ、照明に照らされたナイター、デーゲームの青空と雲）、学校のグラウンドや河川敷などの架空球場もある【事実: 2018 モード「対戦」】。2024-2025 は 30 以上の球場【事実: 2024-2025 モード https://www.konami.com/pawa/2024-2025/mode/】。

### 3-2. 未確認

- メニューのカーソル移動音・決定音・キャンセル音の**音色や長さ**。**未確認**（公式の説明なし）。
- ストライクゾーンの見せ方の**年ごとの変遷**（初代は画面中央にゾーン、四角いカーソル【事実: GAME Watch】。楕円カーソルへの変化の時期などは MATCH §1-3 の範囲外で **未確認**）。

### 3-3. 推測

- 【推測】メニューの音は「**移動＝短く高い 1 音、決定＝上がる 2 音、戻る＝下がる 2 音、押せない＝低い濁った音**」が日本の家庭用ゲームの定番で、パワプロも大きく外れない。本作は `select`（660Hz の 1 音）と `decide` はあるが、**戻る・押せない音がなく、キーボードでフォーカスを動かしても音が鳴らない**（`main.js` はクリックで `decide` を鳴らすだけ）。

- 【推測】アイテムで相手を邪魔する仕組みは、同じ端末で回して遊ぶ（ホットシート）と盛り上がる。オンラインがなくても成り立つ。

## 6. ギャップと提案（P1 / P2 / P3）

評価軸: **パワプロらしさへの効き目**（大/中/小）× **静的ブラウザ・キーボード＋タッチでの作りやすさ**（易/中/難）。既存ノートの提案と重なるものは番号を書き、ここでは**差分だけ**を提案する。
**秒数の約束（全提案共通）**: 1 打席に足す演出は 0.8 秒以内（他の演出と**並行**で鳴らし、待ち時間を増やさない）。節目の演出は 1.2〜2.5 秒、サヨナラだけ 4 秒まで。すべて **Z / Enter / タップで即スキップ**。`reduceMotion()` が真なら動きを止めて文字だけにする。

### P1（効き目が大きく、既存の部品で作れる）

**P1-1. 球審のちびキャラとジェスチャー（効き目: 大 / 易）**
- 差: 声はあるのに姿がない。パワプロ系の画面では判定が「人の動き」で伝わる。
- 提案: 捕手ミット（`c-mitt`）の奥に小さな球審（`chibiHTML` を流用、黒系の服・マスクは独自デザイン）を置く。`feedback` で声と同時に `umpSignal(kind)` を呼び、CSS クラスで腕の形を変える。
  - `strike`: 右拳を斜め前へ（0.35 秒）。空振りは小さく。
  - `strikeout`（見逃し）: 体をひねって拳を大きく突く（0.6 秒）。**空振り三振は普通のストライクの形**（実野球どおり）。
  - `ball`: 動かない（実野球どおり。動かないことが「ボール」の合図になる）。
  - `foul`: 両手をハの字に上げる。
  - `hr`: 人差し指を立てて腕を 2 回まわす（`homeRunFx` の中で）。
  - アウト/セーフは守備ビュー側（FIELDING 提案 P1-4 の塁審）に任せ、ここでは扱わない。
- 声とのずれ: BATTING-PITCHING P3-1 の「捕球音の 150〜250ms 後にコール」と同じ時刻に腕を上げる。
- → `js/game.js`（`template()` に `.chibi-ump`、`feedback` から `umpSignal`）、`css/style.css`（`@keyframes ump-strike / ump-k / ump-foul / ump-hr`）。

**P1-2. 結果のあとのリアクション表（打者・投手）（効き目: 大 / 易〜中）**
- 差: 本作は打つまでのモーションは細かいが、結果に誰も反応しない。初代から「転ぶ・泣き顔・振り返る」が売り【事実 §2-1】。MATCH 提案 #15（空振りでよろける等）は**打席中**の仕草なので、ここでは**結果が出た後**を足す。
- 提案: `applyResult` で結果種別ごとに `react(who, kind)` を呼ぶ。表情は目・口の CSS クラス差し替え（`chibi-eye`/`chibi-mouth` に `.happy` `.sad` `.shock`）。時間は 0.5〜0.8 秒で、結果スタンプと**同時**に出す（待ちを増やさない）。

  | 結果 | 打者 | 投手 |
  |---|---|---|
  | 本塁打 | （既存のバット投げ）＋小さく跳ねる | ひざに手をつく／天を仰ぐ |
  | 長打・タイムリー | 走り出しながら片腕を突き上げる（`batterRunOut` の後半に追加） | 帽子のつばを触る |
  | 見逃し三振 | 首をかしげて球審を一瞬見る | 小さく拳を握る |
  | 空振り三振 | 体が流れたまま、バットを見下ろす | 拳を握る（2 アウト以降・得点圏なら大きく吠える形） |
  | 凡退 | 走り出して途中で減速、肩を落とす | なし（軽くうなずく） |
  | 四球 | バットを置いて一塁へ | 天を仰ぐ |
  | 死球 | うずくまる＋汗マーク（独自の記号） | 帽子を取って軽く頭を下げる（実野球の習慣） |
- → `js/game.js`（`applyResult`、`batterRunOut`、新関数 `react`）、`css/style.css`（表情クラスとキーフレーム）。CPU が打つ/投げる側でも同じ表を使う。

**P1-3. サヨナラ専用の流れ（効き目: 大 / 中）**
- 差: いまはサヨナラでも通常の GAME SET。試合でいちばん盛り上がる場面に専用の演出がない。
- 提案: `afterResult` で「最終回裏・後攻が逆転/勝ち越して試合終了」を判定し `walkoffFx()` へ分岐。
  1. 0.0 秒: 結果スタンプを「サヨナラ！」に差し替え（独自書体の大文字、`ov-stamp` より大きく）、歓声を最大に、BGM を止める。
  2. 0.4 秒: 画面下から味方のちびキャラ 5〜6 体（チーム色）が本塁付近へ駆け寄り、跳ねる。決めた打者は中央で両手を上げる。紙吹雪は CSS の小片 20 個程度。
  3. 2.2 秒: 独自の短い勝利ジングル（`sound.js` に `walkoff`、既存 `fanfare` とは別メロディ）。
  4. 3.5〜4.0 秒: 「GAME SET」を小さく出して結果画面へ。どこでもタップでスキップ（`fxSkip` を流用）。
  - ユーザーが**サヨナラ負け**した側なら、駆け寄る相手チームを遠くに見せ、手前の投手がしゃがむ（2.5 秒で終わる短い版）。
- → `js/game.js`（`afterResult`、新関数 `walkoffFx`）、`js/sound.js`（`walkoff`）、`css/style.css`。

**P1-4. ヒーローは「決勝打」を重く／結果画面をユーザー視点の言葉に（効き目: 大 / 易）**
- 差: MVP は合計点で選ぶため、決勝打の選手が漏れることがある。結果画面の見出しは「○○の勝利！」でユーザーの勝ち負けが分かりにくい（BGM は既にユーザー視点）。
- 提案:
  - エンジンで**決勝打**（最後に勝ち越した得点を挙げた打席の打者）を記録: `state.gwBatterId`（得点で勝ち越した瞬間に上書き、追いつかれたら消す）。`boxScore` の MVP 点数に `+3`（サヨナラなら `+4`）。
  - 結果画面に「ヒーロー」カード: ちびキャラ（既存 `chibiHTML`、勝ちポーズのクラス）＋**独自の一言**を `js/commentary.js` に `heroLine(box, state)` として追加（例: 「決勝打の場面は、真っすぐだけを待っていました」— 実在のコメントや決め台詞は真似しない。10〜20 パターン）。
  - 見出しをユーザー視点に: 「勝利！」「惜敗…」「引き分け」＋小さく「○○ 3-2 ○○」。`main.js` が既に持つ `userSide` を `renderResult` に渡す。
- → `js/engine.js`（`gwBatterId` の更新、`boxScore` の MVP 点）、`js/screens.js`（`renderResult` にヒーローカードと見出し）、`js/commentary.js`（`heroLine`）、`tests/`（決勝打の判定テスト）。

**P1-5. 攻守交代に「イニング別スコアボード」の帯（効き目: 中〜大 / 易）**
- 差: 交代時は文字だけ。パワプロ系も実際の中継も、回の変わり目は**スコアボード**で「いまどんな試合か」を見せる（実際の秒数は **未確認**）。
- 提案: `afterResult` の交代時、`showOverlay` の代わりに `showInningBoard()` を 1.6 秒（タップでスキップ）: 上段に「3回表 終了」、中段に両チームの回ごとの得点（`state.score.away/home` をそのまま。結果画面の `.linescore` の CSS を共用）、下段に「次の攻撃: ○○ 4番から」。**得点が入った回だけ 0.3 秒光らせる**。3 アウト目の直後 0.4 秒は野手がベンチへ駆け出す小さな動き（2018 の「3 アウト後に全力で走る」【事実】を独自の絵で）を見せてから帯を出す。
- → `js/game.js`（`afterResult`、新関数 `showInningBoard`）、`css/style.css`（`.inning-board`）。`CHANGE_MS` を 1600 に。

### P2（試合の厚み。手間は中）

**P2-1. 投手交代の「紹介プレート」（効き目: 中 / 易）**
- 差: 交代は文字のオーバーレイだけで、新しい投手がどんな投手か分からない。
- 提案: `showSubs` が投手交代なら、オーバーレイの代わりに 1.4 秒のプレート: 背番号・名前・利き腕・「最速 ○km/h」・球種（`p-pitches` と同じ部品）・特殊能力チップ。同時にマウンドの `chibi-pitcher` を画面外から走って入らせる（0.5 秒）。ユーザーの打席中に CPU が投手を代えたときは「ここで投手交代」の実況を 1 行。
- → `js/game.js`（`showSubs`、新関数 `pitcherIntro`）、`css/subs.css`。

**P2-2. 試合開始の流れ（MATCH 提案 #21 の具体化）（効き目: 中 / 易）**
- 提案（合計 2.5 秒、Z/タップで最後へ飛ぶ）: ① 0.0〜0.8 秒「チーム A VS チーム B」（チーム色の帯が左右から入る）② 0.8〜1.8 秒 両軍のスタメン 9 人を名前と守備位置で左右に一気に並べる（1 人ずつ流さない。テンポ優先）③ 1.8〜2.5 秒 球審（P1-1）が右腕を伸ばして指さす「プレイ」のジェスチャー＋声（既存の音声に「プレイボール」がなければ `speechSynthesis` か短い効果音）。2 試合目以降は設定で ②を省略可。
- → `js/game.js`（初期化末尾の `showOverlay` を `openingFx()` に置き換え）、`css/style.css`。

**P2-3. 新聞見出し風の結果（効き目: 中 / 中）**
- 根拠: 栄冠ナインの新聞（見出し 50 種以上、重要な試合ほど大きく写真入り）【事実 §1-1】。仕組みだけ借り、紙面のデザイン・見出し文は独自に作る。
- 提案: 結果画面の上部を「スポーツ紙の 1 面」風に。`headlineFor(box, state)` が試合の特徴を点数化して見出しを選ぶ: サヨナラ／逆転／完封／2 桁得点／先発全員安打／1 点差／延長／大敗。重要度で文字の大きさと「写真」（ちびキャラの勝ちポーズを紙面風に網点フィルターで）を変える。小見出しは「○○、2 打点の活躍」のように**選手名入り**。
- → `js/screens.js`（`renderResult`、新関数 `headlineFor`）、`js/commentary.js`（見出しの文面）、`css/style.css`。

**P2-4. 「場面から始める」短時間モード＋すぐリトライ（効き目: 中 / 中）**
- 根拠: 公式の「おいしいところだけプレイ」と「いつでもリトライ」【事実 §4-1】、10 球練習【事実】。SYSTEMS 提案 #22（1 打席チャレンジ）・#23（スコアアタック）は**打席を順に戦う**形なので、こちらは**状況を固定**する。
- 提案: タイトルの「10球チャレンジ」の隣に「場面チャレンジ」。5〜8 個の固定場面（例: 9 回裏 2 死満塁 1 点差／延長タイブレーク無死一二塁／7 回 1 死三塁で外野フライが欲しい）を、`engine.createGame` の後に `state` を上書きして始める（回・アウト・走者・点差・カウント）。成功条件（サヨナラ、同点、犠飛など）を満たせば星 1〜3。失敗したら**結果画面を出さず**「もう一度」ボタン（同じ乱数シードで同じ投手・同じ配球の順を再現するか、シードを変えるかを選べる）。記録は localStorage。
- → 新規 `js/scenario.js`（場面の定義と判定）、`js/main.js`（起動・リトライ）、`js/title.js`（入口）、`js/game.js`（`opts.scenario` を受けて `afterResult` で成功判定し、試合終了の代わりにコールバック）。

**P2-5. UI の効果音を 4 種にそろえる（効き目: 中 / 易）**
- 差: 決定音しかなく、戻る・押せない・フォーカス移動で音がない。キーボード操作で手触りが薄い。
- 提案: `sound.js` に `move`（短い高い 1 音、40ms）、`back`（下がる 2 音）、`buzz`（低い濁った 1 音、押せないボタン・選べない選手）を追加。`main.js` の keydown でフォーカスが動いたら `move`、Esc/「もどる」で `back`、`disabled` のボタンを押したら `buzz`。タッチでは `move` を鳴らさない（うるさいため）。音は既存の矩形波合成で、どこかのゲームの音に似せない。
- → `js/sound.js`、`js/main.js`（クリック/キー処理）、`js/screens.js`・`js/title.js` の「もどる」ボタンに `data-snd="back"`。

**P2-6. 演出のスキップと長さを 1 か所で管理（MATCH 提案 #22 の土台）（効き目: 中 / 中）**
- 差: スキップできるのは HR 演出だけ。交代・GAME SET は時間で消えるのを待つ。
- 提案: `presentFx(steps, { skippable: true, key })` を作り、各演出（開始・交代・投手紹介・サヨナラ・HR）を「手順の配列（時刻・関数）」で渡す。Z/Enter/タップで残りの手順の**最終状態**だけを適用して次へ。設定に「演出: ふつう／みじかい／なし」（`main.js DEFAULTS.fx`）。「みじかい」は各演出を 0.5 倍、「なし」はスコアボード帯と投手紹介を 0.6 秒の文字だけに。2 回目以降に同じ演出（例: 同じ投手の紹介）は自動で「みじかい」。
- → `js/game.js`（`showOverlay`・`homeRunFx` を `presentFx` 経由に）、`js/main.js`（設定）、`js/screens.js`（設定画面）。

**P2-7. 打席入りの小さな仕草（効き目: 小〜中 / 易）**
- 根拠: 初代の「足元をならす」【事実 §2-1】。
- 提案: 新しい打者が入るとき（`enterReady` の `newAtBat`）に 0.4 秒の「打席に入る」動き（右から歩いて構える、またはバットで足元を 2 回つつく）。2 ストライク後に一度だけ打者が打席を外して素振り 1 回（0.5 秒、CPU 投手の間に並行）。ユーザーの入力は止めない。
- → `js/game.js`（`enterReady`、`playBatterKeys` に `step-in` キー列）、`css/style.css`。

### 提案しないもの（理由）

- **実在の球場・応援歌・実況アナウンサーの声や言い回しの再現**: 権利と独自性の方針に反する。
- **選手ごとの打撃フォームを数百種類**: 効き目に対して手間が大きすぎる。既存提案（BATTING-PITCHING P2-6）の数種類で十分。
- **長い紹介デモ（10〜15 秒）**: ブラウザの短時間プレイに合わない。本作は 1 回 2.5 秒以内に抑える。
