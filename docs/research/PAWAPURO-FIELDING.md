## 0. 要点（先に結論）

1. **パワプロでは打球も盗塁も必ず「守備・走塁画面」で見せる**。打った側は走者を操作し、守った側は野手を操作する（どちらもオートにできる）。本作はユーザーが打っている間、既定設定では**打球が捕手視点の画面で落下点の印へ飛ぶだけ**で、野手も走者も動かない（`js/game.js` `autoInPlay`）。「野球らしい動き」が一番見えるはずの場面が、いちばん省略されている。→ **P1-1**
2. **攻撃側の操作（走塁）が本作にはない**。パワプロの打者は打った後も「回せ/戻れ/止まれ」を判断する。→ **P1-2**
3. **送球ミスが本作にはない**（エラーは捕球時の落球だけ）。パワプロは送球の能力（逸れにくさ）が段階で分かれ、上位能力もある。→ **P1-3**
4. **際どい判定の見せ方**（塁審のジェスチャー、スロー、タッチの動き、滑り込みの種類）が本作は文字のコールだけ。→ **P1-4**
5. 中継（カットマン）・送球のカット・二つ目の送球・挟殺・ジャンプ／フェンス際の捕球・リプレイは、パワプロにあって本作にない。効き目と手間の順に P2/P3 に並べた（§6）。

## 1. 守備操作（事実）

### 1-1. 操作のしくみ
| 内容 | 出典 |
|---|---|
| 操作できるのは頭上に▼が付いた野手。▼は**操作中に点滅**する。他の野手は自動で動く（ベースカバーも自動）。 | 【公式】2016 説明書 p.06・p.07 ／【攻略】pawasuq |
| 操作選手は基本的に**ボールに一番近い野手**へ自動で移る。ボタンを**押している間は操作選手を固定**できる（2016: L1 相当、2025 の解説: R1 を押したまま）。別のボタンで近くの別の野手へ切り替え。 | 【公式】2016 説明書 p.06 ／【攻略】kumanote 基本編 |

### 1-3. ファインプレー（既出の補足：使い分けと失敗の代償）
| 内容 | 出典 |
|---|---|
| 方向＋ボタンで**横っ飛び**（リーチは長いが近い打球は通り越す）。ボタンだけで**真上にジャンプ**、方向＋別ボタンで**斜め上へジャンプ**（ライナー・ポテン性向け、ゴロには不向き）。**状況に応じて自動で選ぶアクション**は範囲がやや狭いが、捕球間際に押すと手を伸ばして止められることがある。前進しながらの際どいフライでは**スライディングキャッチ**になる（落としやすい）。 | 【公式】WBSC プレイガイド p.13 ／2016 説明書 p.06 ／【攻略】kumanote ジャンプ編 |
| 古い世代の解説では、動作ごとに**動作後の硬直**が違う（伸ばしキャッチ・垂直ジャンプは短い、斜めジャンプ・横っ飛びは長い。垂直ジャンプは空中から送球できる）。 | 【攻略】pawasuq（シリーズ共通とされる。現行作で同じかは**未確認**） |
| **フェンス際**: フェンスに向かって押しながら走ると**よじ登り**、直撃・本塁打性の打球をダイレクトで捕れる。登っていられるのは短時間。フェンスに飛び込んで激突すると**硬直が長く、ケガ**のおそれ。 | 【公式】2016 説明書 p.06 ／【攻略】kumanote ジャンプ編 |
| 失敗の代償: 外野で逸らすと起き上がりに時間がかかる。前進して逸らすと後ろへ抜ける。内野はダイビングで止めればシングルで済むので強気でよい、外野は追い込まれた時だけ。 | 【攻略】kumanote ジャンプ編 |

| `js/game.js` `handleContact` | ユーザーの**守備中**: `fieldMode` が auto なら即解決、assist/manual なら守備ビュー（`startInPlay`→`openFieldView`）。ユーザーの**攻撃中**: `fieldMode==='manual'` のときだけ CPU 守備ビューを 1.5 倍速（`CPU_FIELD_SPEED`）で見せ、それ以外（**既定の assist を含む**）は `autoInPlay`＝捕手視点の画面で打球が落下点マーカーへ飛ぶだけ（`animateInPlay`）。 |
| `js/game.js` `finishInPlay` | 守備ビューの結果（`result`）を `engine.resolveBattedBall` に渡す。打球 1 つにつき 1 回だけ解決。 |
| `js/fielding.js` | 2.5D の**全景固定カメラ**。野手の役割 AI（追う/後方支援/ベースカバー/寄る/拾う）、自動捕球、ダイビング（Z、成功率は守備力と距離）、操作選手の切替（X、近い順に上位 4 人を巡回、固定はなし）、送球先選択（矢印/塁タップ、assist は送球選択中 0.4 倍スロー、1.2 秒で自動送球）、走者の膨らみ・一塁駆け抜け・スライディング（見た目）、送球の山なり（見た目、`throwPos`）、OUT タグ、到達時の「アウト！/セーフ！/ゲッツー！」のコール。判定は `previewPlay` でエンジンと一致。 |
| `js/fielding.js` 走者 | 走者は**全自動**（`syncRunners` がエンジンの計画に合わせる）。ユーザーの走塁入力はない。落下点の印は**色が変わらない**（`.fv-landmark` は常に黄色の点線）。 |
| `js/engine.js` `intercept` | 3 段階（ノーバウンド捕球 → バウンド後 → 止まった球を拾う）。野手は反応時間の後に**一定速度**、方向やフェンスの影響なし。 |
| `js/engine.js` `planRunners` | 決定的。走者ごとに各塁の到達時刻、打球の種類・アウト数・封殺で出発時刻を決め、「ボールより `margin` 早く着けるなら次の塁へ」。タッチアップは捕球後スタート。 |
| `js/engine.js` `chooseThrow` | CPU の送球先（内野ゴロは本塁→三→二の封殺、だめなら一塁。外野は先の塁から間に合う所）。**送球は 1 回だけ**（例外: 併殺の一塁転送 `relay`、打者走者の送球間進塁 `onThrow`）。 |
| `js/engine.js` `computePlay` | 送球到達＋（タッチなら `tagTime`）と走者の到達の比較でアウト/セーフ。送球誤差は**時間の揺れ**（`throwNoise`）のみ。**悪送球なし、中継（カットマン）なし、挟殺なし、本塁クロスプレーの特別扱いなし**。エラーは捕球時のみ（`errBase`、`errDelay` 1.5 秒の遅れ）。 |
| 盗塁 | `stealTimes` の時間比較（ポップタイムは実野球と整合）。画面は打撃画面のまま（`showStealRunner`）。 |
| リプレイ | なし。 |

## 6. 差分と提案（P1/P2/P3）

**並べ方**: 「野球らしさ」への効き目 × 静的ブラウザゲーム（キーボード＋タッチ）での作りやすさ。名前はすべて本作独自。

### P1（効き目が大きく、既存の部品で作れる）

**P1-1. ユーザーの打球と盗塁を、毎回「観戦用の守備ビュー」で見せる**
- 差: パワプロは打球も盗塁も守備・走塁画面に切り替える（§2）。本作は既定設定で、ユーザーが打った打球の野手・走者の動きを見せていない（§5）。
- 提案: `js/game.js` `handleContact` の分岐を「ユーザー攻撃中は `startInPlay`（`mode:'cpu'`, `timeScale 1.5`, `tapToSkip`）」に変える。設定 `ctx.settings.watchPlays`（`'full'`=常に／`'big'`=長打・走者ありのときだけ／`'off'`=従来）を `js/screens.js` のせってい画面に追加（既定 `'big'` でテンポと両立）。盗塁は `runSteal` のイベントを受けて、`js/fielding.js` に **盗塁専用の短い再生**（`createFieldingView` に `opts.steal={from,to,runnerTime,throwTime,safe}` を渡し、捕手→塁の送球と走者の滑り込みだけを 2 秒で再生）を足す。
- 作りやすさ: 高（CPU 守備ビューは既にある）。テンポ対策として `'big'` 既定と、再生中どこでもタップでスキップ（既存）。

**P1-2. 走塁の指示（攻撃側の操作）**
- 差: パワプロの打者は「全員進め／全員戻れ／1 人だけ指定／塁間で止まれ」を操作できる（§2）。本作の走者は全自動。
- 提案（操作）: 観戦ビュー（P1-1）で、キーボード **↑=全員すすめ ↓=全員もどれ ↑+↓=止まれ**、**1/2/3 キー＋↑↓=その塁を目指す走者だけ**。タッチは画面下に「すすめ」「もどれ」の 2 ボタン、走者のトークンをタップで個別選択。設定「走塁: おまかせ／自分で」（既定おまかせ、`fieldMode` と同じ形で `js/main.js` DEFAULTS に追加）。
- 提案（実装）: `js/fielding.js` `stepRunners` で、ユーザーの指示があれば `r.goal` を上書き（現状の `syncRunners` より優先）。CPU 野手の送球は既に現在の走者位置から `smartBase()` で選ぶので、指示に反応する。最終判定は `js/engine.js` に `fielding.runOrders = {runnerId: targetBase}` を受け取る口を作り、`planRunners` で `r.target` を「指示の塁（封殺の最低塁以上・前の走者を追い越さない）」に置き換える。打者走者の一塁オーバーラン中の帰塁も同じ口で扱う。`previewPlay` も同じ引数を受けるので見た目と判定は一致したまま。
- 作りやすさ: 中（エンジンの口 1 つ＋入力）。

**P1-3. 送球ミス（悪送球・ショートバウンド・受け手の捕り損ね）**
- 差: パワプロは送球の逸れにくさが能力の軸（✕〜◎と上位能力）で、長い送球ほど逸れる（既出）。本作は送球が必ず正確。
- 提案（判定）: `js/engine.js` `computePlay` の送球処理に「逸れ量」を足す: `miss = base × 距離係数(d/30) × (1.3 − 守備力/99) × 急ぎ係数(残り時間が少ないほど大) × 能力補正(送球◎ 0.6、新しい赤特「送球が不安定」1.6)`。`miss` が大きいと (a) 受け手が伸び上がって時間 +0.25 秒（アウト→セーフになりやすい）、(b) まれに後ろへ逸れて**全走者が 1 つ進む**（`kind:'error'`、記録は送球エラー）。目標は送球エラーが 1 試合両軍 0.1〜0.2 個（実数は `tests/balance.mjs` で調整。エラー全体は NPB 程度に保つ）。乱数は `rng` があるときだけ（`previewPlay` は誤差なしのまま、守備ビューでは逸れ量を先に決めて `fielding.throwMiss` で渡す）。
- 提案（見た目）: `js/fielding.js` `throwPos` に横ずれ・ワンバウンドの軌道、受け手の `fv-stretch`（既存ポーズ）を逸れた方向へ。後ろへ抜けたら後方支援の野手（`role:'backup'`）が拾う動きを再利用。
- 作りやすさ: 中。

**P1-4. 際どい判定の「間」と動き（塁審・スロー・タッチ・滑り込み）**
- 差: 本作は送球到達時に文字のコールが出るだけ。パワプロ側の詳細は未確認だが、実野球の見どころはここ（§4）。
- 提案（すべて見た目、`js/fielding.js`）:
  1. 到達時刻の差 `|走者到達 − アウト時刻| < 0.15 秒` を「際どい」とし、到達の 0.4 秒前から 0.35 倍スロー（`frame()` の `acc` に掛ける。現状の送球選択中スローと同じ仕組み）。
  2. 塁のそばに**塁審のトークン**（帽子＋黒い服の 2 頭身、本作の絵柄）を置き、判定で「両腕を横に広げる（セーフ）」「拳を上げる（アウト）」の CSS ポーズ（`js/fielding.js` の `tokenEl` を流用、`css/fielding.css` に 2 ポーズ）。コールの文字は 0.2 秒遅らせてジェスチャーの後に出す。
  3. タッチプレー（封殺でない塁）は受け手がグラブを走者側へ払う `fv-tag` ポーズ、封殺は塁を踏む `fv-stretch`。
  4. 滑り込みの種類を差で選ぶ: 余裕セーフ＝立ったまま、際どい＝足から、きわどい＋走力が高い＝頭から、本塁でタッチを避ける＝回り込み（手でベースを払う）。`r.slide` を種類つき（`'feet'|'head'|'hook'`）にする。
- 作りやすさ: 高（判定は変えない）。

### P2（試合の厚み。手間は中）

**P2-1. 中継（カットマン）と送球のカット**
- 差: パワプロは外野からの送球を中継へ投げるボタン、本塁送球を投手がカットするボタンがある（§1-2）。本作は外野からも直接投げ、`longThrow` の時間ペナルティだけ。
- 提案: `js/engine.js` に `relaySeconds(F, C, from, base)` = 持ち替え + d1/v外野 + 中継の持ち替え(0.45 − 0.15×守備力) + d2/v中継。`chooseThrow`/`throwSeconds` で直接と中継の速い方を CPU が選ぶ（肩の弱い外野手・60m 超で中継が勝つ）。`js/fielding.js` は外野が捕った瞬間に二塁手か遊撃手が**外野と塁を結ぶ線上**へ出る動き（`role:'cutoff'`）と、2 段の送球を描く。ユーザー守備（manual/assist）では X（タッチは「中継」ボタン）で中継を選べる。本塁送球の途中で投手・一塁手がカットして**後ろの走者を刺す**判断は CPU のみ（`computePlay` で、本塁が間に合わず打者走者が二塁を狙うとき）。
- 作りやすさ: 中。

**P2-2. 二つ目の送球（送球の間の進塁と、それを刺すプレー）**
- 差: 本作は送球が 1 回で終わる（併殺の転送と打者の `onThrow` を除く）。実野球では「本塁送球の間に打者が二塁へ→捕手が二塁へ送球」がよくある。パワプロの扱いは**未確認**。
- 提案: `computePlay` を「送球 → 次の送球」の小さなループにし、2 回目は残りの走者のうち最も刺しやすい者を狙う（最大 2 回）。`fielding.js` の `phase:'throw'` 終了時に `verdict.next` があれば `doThrow` を続けて呼ぶ。
- 作りやすさ: 中。

**P2-3. 守備ビューの情報表示（落下点の色・担当野手・走者の小図）**
- 差: パワプロは落下点に入ると色が変わり、担当野手名・走者の小さなダイヤモンド・風を出す（§1-1, §2）。本作の落下点は色が変わらず、走者の小図もない（全景なので走者は見えるが、どこまで回るかは分かりにくい）。
- 提案: `js/fielding.js` `render()` で、操作中（または追う役）の野手が `catchR` 内に入ったら `.fv-landmark` に `.in` を付けて**緑の実線＋チェック**（本作の色）。HUD の `fv-who` に「捕る人: 中 ○○」。走者の目標塁を塁マーカーの上に小さな矢印で出す（`r.goal` から）。風は本作にないので出さない。
- 作りやすさ: 高。

**P2-4. ジャンプ捕球の追加（ダイビングと使い分け）**
- 差: パワプロは横っ飛び・真上/斜めジャンプ・自動選択の 3 系統（§1-3）。本作はダイビングのみで、`REACH_Z 2.8` より高いライナーは捕れない。
- 提案: `js/fielding.js` `tryDive` を「打球の高さ `z` が 2.2m 以上ならジャンプ（到達高さ +0.9m、横の伸び 0.6m、硬直 0.3 秒）、それ以外はダイビング（現状）」に自動で分ける（ボタンは Z のまま＝自動選択系）。エンジン側は `intercept` の `catchHeight` を、ユーザーがジャンプしたときだけ `makeFielding` 経由で許す（`input.jump:true` で z 判定を +0.9）。
- 作りやすさ: 中（判定を広げるので `tests/` で安打率を確認）。

**P2-5. 守備・走塁の特殊能力を「軸」で追加（独自名）**
- 差: §3 の 5 軸のうち、本作は背走・送球の軌道・正確さ・本塁の攻防がない。
- 提案（`js/data.js` `SKILLS` と `js/engine.js` の `SKILL_FX`、名前は仮の独自名）:
  | 独自名（案） | 種類 | 効果（本作の実装） |
  |---|---|---|
  | 背走名人 | 青 | 打球が自分より後ろ（本塁から遠ざかる方向）のとき移動速度 +8%（`intercept` で方向判定） |
  | 一直線返球 | 青 | 外野手の送球速度 +3 m/s、見た目の山なり半分（`throwSeconds`・`throwPos`） |
  | 精密スロー | 青 | P1-3 の逸れ量 ×0.5（`送球◎` の正確さ部分を分離してもよい） |
  | 送球が不安定 | 赤 | 逸れ量 ×1.6 |
  | 前進ダッシュ | 青 | バント・ボテボテのゴロで反応 −0.15 秒（`fielderParams` の `react`、`ball.bunt` 時） |
  | 本塁の番人 | 青（捕手） | 本塁のタッチプレーで `tagTime` −0.05 秒、P2-6 の落球誘発を無効 |
  | 好走判断 | 緑 | `planRunners` の `margin` −0.15（積極的に次の塁へ。暴走もある） |
  | 飛び込みスライド | 青 | 際どいとき到達 −0.05 秒（見た目は頭から） |
  | 大事な場面でもたつく | 赤 | 得点圏に走者がいるとき失策率 ×1.5（既存 `エラー` に状況条件を足す形でもよい） |
- 作りやすさ: 中（1 つずつ小さい）。名前は `PAWAPURO-SYSTEMS.md` §2-5 の点検ルールで確認する。

**P2-6. 直前のプレイを再生（リプレイ）**
- 差: パワプロは守備・走塁画面からボタン長押しで直前のプレイを再生（§4）。本作はなし。
- 提案: `js/fielding.js` で 0.1 秒ごとに `{t, 野手 x/y/pose, 走者 p, ボール x/y/z}` を記録（1 プレイ 20 秒で 200 件程度）。`onDone` の後、結果オーバーレイに「もう一回見る（R / タップ）」を出し、記録を 0.5 倍で再生する `replay()` を返り値に足す（シミュレーションは回さないので判定に影響しない）。際どい判定（P1-4）と長打のときだけボタンを出す。`js/game.js` `applyResult` から呼ぶ。
- 作りやすさ: 中。

### P3（仕上げ・遊びの幅）

- **P3-1. 操作選手の固定**: X 長押しで固定、短押しで切替（パワプロは押している間固定）。`js/fielding.js` `handleKey` に押下時間を足す。手間: 低。
- **P3-2. 強い送球（長押し）**: 送球ボタンを 0.3 秒以上押すと速度 ×1.1・逸れ量 ×1.8（P1-3 の後）。手間: 低。
- **P3-3. 送球キャンセル／投げる塁の変更**: 送球直後 0.15 秒以内に別の塁を押すと投げ直す（持ち替え +0.3 秒）。手間: 低〜中。
- **P3-4. 挟殺（塁間で挟む）**: 送球ミスや飛び出し（P1-2 の帰塁遅れ）で走者が塁間に止まったとき、2 人の野手が投げ合い、走者は戻る/進むを繰り返す小さな状態機械。結果は「走力と野手の守備力」で確率的に（`computePlay` に `rundown` イベント）。見た目は `fielding.js` に専用 phase。手間: 高。
- **P3-5. フェンス際の本塁打阻止**: `ball.isHomeRun` かつフェンス到達時の高さがフェンス高 +1.0m 以内なら「よじ登り捕球」の判定（外野手の守備力と到達時間で数 %）。エンジンで本塁打を決めてから守備に入る順序なので、`pitchContact` で `ball.robbable` を付けて `resolveBattedBall` が out にできるようにする。手間: 高（記録とバランスに影響）。
- **P3-6. 判定への異議（独自の「ビデオ確認」）**: ユーザーに不利な際どい判定（差 0.05 秒未満）のあと、1 試合 2 回まで（NPB に合わせる）「ビデオ確認」ボタン。リプレイ（P2-6）を 0.25 倍で見せ、判定は**エンジンの判定どおり**（本作は判定が正しいので「判定どおり」の演出が基本）。もし審判の見誤りを入れるなら、際どい判定の 10% で最初のコールを逆にし、確認で覆る（記録は覆った後）。手間: 中、遊びとして好みが分かれるので設定で。
- **P3-7. 守備ビューのカメラ**: 全景固定のまま、内野の打球では `.fv-layer` と背景 SVG に `scale(1.25)` を打球位置中心でかけて寄る（パワプロの「守備ズームカメラ」設定の考え方。中身は未確認）。`prefers-reduced-motion` では無効。手間: 中。
- **P3-8. 野手の加速と方向**: `intercept`（engine）と `moveToward`（fielding）に「最初の 0.5 秒は 70% の速さ」「後ろへ下がるときは 90%」を入れる（実野球の Jump・Catch Probability の考え方）。守備範囲が狭くなるので `reachAir` を少し上げて釣り合わせる。手間: 中（両ファイルを同時に変えて判定一致を保つ）。
- **P3-9. 打者の左右で一塁到達を変える**: 左打者 −0.1 秒（実野球: 左打者は一塁に近い）。`planRunners` の `bat1B`。手間: 低。
