# パワプロ研究（B）: 試合システム・数値・モード

調査日: 2026-10-11 ／ 担当範囲: **B = ゲームシステム・数値・モード**（操作感・演出・キャラ造形は docs/PAWAPURO-RESEARCH.md 側）
対象: KONAMI『実況パワフルプロ野球』シリーズ（主に 2020〜2026-2027 世代、『WBSC eBASEBALL パワフルプロ野球』、パワプロアプリ）と NPB 2023〜2025 の実データ

> **方針**: 本作はパワプロに着想を得たオリジナル作品。KONAMI の名称・文章・画像・音声は使わない。ここに書くのは**仕組みと数値の傾向**を自分の言葉でまとめたもの。実装では名称・係数を独自のものにする。
> docs/PAWAPURO-RESEARCH.md（2026-10-10, 浅め）にある内容は繰り返さず、**数値・仕様の深掘り**と**本作の現行コードとの差分**に集中する。

**信頼度の表記**
- 【公式】KONAMI の公式サイト・電子説明書・公式ヘルプ
- 【検証】攻略ブログ・wiki の実測（作品・条件で変わる）

**本作の製品方針（前提）**: ユーザーは**打撃のみ**操作。ユーザーチームの守備中は CPU が自動で投球し、守備も自動（別の守備画面なし）。試合は即開始。
→ パワプロの仕組みのうち「打席の中身（投手の質・配球・調子・特能・失投）」と「試合の流れ（継投・采配・テンポ）」が体験の大半を決める。投球操作・守備操作の研究は優先度を下げた。

## 0. 要点（先に結論）

1. **能力は「足し算の補正」で動く。** パワプロの特能・調子は「ミート+15」「球速+2km/h」のような**能力値への加算**が基本で、結果確率を直接いじるのではない。本作は確率の重みに倍率を掛ける方式なので、UI で効果を説明しにくい。→ 加算式の `effectiveStats()` に寄せると、表示・調整・テストが楽になる（バックログ P1-3）。
2. **調子は大きい。** 打者は 絶好調 ミート・パワー各 +15・弾道 +1、絶不調 −15・−1【検証】。本作の ×1.10〜×0.90（ミート 70 なら ±7）は約半分の振れ幅。
3. **スタミナは「1球ごとの消費 ＋ 出来事による消費」。** 球種で 27〜63、走者がいると +3〜+10、被安打 30〜80、失点 40〜80 を引く【検証】。だから打ち込まれると球数が少なくても降板する。本作は 1球=1（ストレート系 0.5）だけ。
4. **失投（甘い球）の確率が明示的にある。** 普段は約 10%、赤特「一発」で約 20%、「逃げ球」で約 5%【検証】。打撃だけ操作する本作では「甘い球を仕留める」体験の源になる。本作には失投の仕組みがない。
5. **NPB 2023〜25 の 1 試合（両軍）**: 得点 6.4〜7.0、安打 15.9〜16.6、本塁打 1.1〜1.5、三振 13.9〜14.7、四球 5.2〜6.0、死球 0.6〜0.8、盗塁 0.8〜1.2（成功率 約 70%）、犠打 1.1〜1.6、併殺打 1.2〜1.4、失策 約 1.0【推計: NPB 公式のチーム成績から計算】。本作の CPU 同士は 得点 8.6・安打 18.9 と**やや打高**、**犠打 0・死球 0・暴投 0・盗塁成功率 88%**。
6. **打撃だけ操作するモードには公式の前例がある。** ペナントの「出番プレイ（特定の場面だけ操作）」【公式 2016 説明書】、パワプロアプリ「スタジアム」の「試合は自動、大事な場面だけ操作」【公式】、2024 の「1 打席勝負を重ねて 100 人抜き」モード【攻略】。本作の方針に合う。

### 1-2. ランクと数値の分布

- 数値は 1〜100、表示は **S〜G の 8 段階**【公式/報道】。境界（S90/A80/B70/C60/D50/E40/F20）は広く使われているが、**一次資料では未確認**（前回調査と同じ結論）。
- **実在選手の分布はかなり辛い**: 2023 年終了時点のデータで、現役 NPB のミート最高は 69（C）。セの首位打者（打率 .326）でミート 63、パの首位打者（.307）で 53。開発者は「ミートを B にすると打率 .330 前後になりかねない」「特能が多い選手はミートを下げて釣り合いを取る」と説明している【報道: デイリー 2024-07】。
- 能力値は外部提供の成績を社内ツールで変換し、担当者の分析と**複数年の実績**を加味して決める（単年の活躍をそのまま反映しない）【報道: 文春オンライン】。
- 本作との関係: 本作の data.js は「打率 .300 → ミート 72」と**パワプロより約 10 高い換算**。本作は特能の効果が弱め（倍率 1.1〜1.2 程度）なので、この換算で釣り合っている。特能を加算式に強めるなら、ミートを数ポイント下げる再調整が必要。

出典: https://www.daily.co.jp/gossip/subculture/2024/07/13/0017880020.shtml ／ https://bunshun.jp/articles/-/46627?page=3

### 1-3. ミートとカーソル

- ミートが高いほどカーソルが大きい【公式】。2020 で**最小サイズが縮小**され、低ミートほど当てにくくなった。ミート C 以上はそれまでとほぼ同じ大きさ、という体感報告【検証: プロ選手ブログ】。→ **大きさは能力に比例ではなく、低い側で急に小さくなる曲線**と考えられる。
- 「三振」（赤）は 2 ストライク時にミート −20、「扇風機」（その上位の赤）は −30。「粘り打ち」は 2 ストライク時（ミート打ち）にミート +10【検証】。→ 2 ストライクでカーソルの大きさが変わる、という形で効く。
- ランク別のカーソル寸法: **未確認**（実測の公開データなし）。

### 1-4. パワーと弾道（＝打球速度と打球角度）

- 「パワー＝打球速度、弾道＝打球角度」という対応は公式の説明（パワー＝打球の強さ・飛距離、弾道＝上がりやすさ）と整合し、データ分析サイトも同じ読みをしている【公式＋1.02 コラム】。
- 弾道 4 のセンター返しで約 140m、140m を超えるとほとんど伸びない【検証: 2022】。弾道 4 は 3 より最大飛距離が約 3m 長い【検証: 2019】。
- パワー 10 あたりの飛距離差は一定ではなく、A〜S 付近で約 4〜6m、S を超えると約 1.5m に縮む【検証: パワプロアプリ】。→ **高い側で頭打ちになる曲線**。
- パワーが低い打者の弾道を上げると、凡フライが増えて打率が下がる（パワー D 程度あれば緩和）【攻略】。

出典: https://1point02.jp/op/gnav/column/bs/column.aspx?cid=53637 ／ https://media-salon.com/archives/3322 ／ https://maepi.hatenablog.jp/entry/2022/05/09/102652 ／ https://lemniscate.hatenablog.jp/entry/2019/07/12/230402 ／ https://note.com/ppapplab/n/n6bcfe0b4ae77

### 1-5. 走力と塁間

- 実在選手の査定では、一塁到達タイムの平均を**左打者 4.2 秒・右打者 4.3 秒**とし、左打者で 3 秒台なら俊足の目安【検証: 査定考察ブログ】。
- 走力ランクと秒数の公式対応表: **未確認**。
- 「走塁」特能は加速型で、本塁→一塁の到達時間はほとんど変わらないという指摘【攻略】。
- **本作**: 打者の一塁到達が 4.6〜4.9 秒（`TUNING.bat1BFast/bat1BSlow`）。実際より 0.3〜0.5 秒遅く、左右差もない。

出典: https://pawapuro-lab.com/entry/evaluation_running

### 1-6. 投手能力

**球速**: 調子で上下する【公式】。本作は `velocityAbility = (km/h − 120)/50 × 99` に変換して空振り率に効かせている。

**コントロールと失投**【検証: 2022/2023 世代】
- 失投（狙いが外れて**ど真ん中に入る**球）の確率は通常 **約 10%**。赤特「一発」で 2 倍の約 20%、青特「逃げ球」で約 5%。上位の金特では「真ん中に入ることがほぼなくなる」系の効果がある。
- 2020 では失投が「棒球に近い挙動」に変更された（甘く、変化も弱い）【公式: 2020 開発ブログ】。
- 赤特「荒れ球」はブレ幅を広げる（コントロール −20 相当）。

**スタミナ（2024-2025 の実測）**【検証: price-shopping の調査】

### 1-7. 査定（総合力）

- **公式の計算式は非公開**（未確認）。分かっていること:
  - パワプロアプリでは、能力値ごと・特能ごとに査定値の表があり、**高い能力ほど 1 ポイントの査定が大きい**（逓増）【攻略: パワプロアプリ wiki の査定表】。
  - チーム総合力は「スタメン野手とエースの査定はそのまま、控えは約 1/10 だけ反映」【攻略: パワプロアプリ】。
- 実在選手の能力の作り方（ファンの査定基準）【検証】:
  - コントロール ← 与四球率（先発 BB/9: 1.0 → 90、2.0 → 80、2.5 → 70、3.0 → 60、3.5 → 50、4.0 → 40、5.0 → 30）
  - スタミナ ← 先発: 平均投球数 ÷ 1.5 ＋ 完投数 × 2、救援: 平均投球数 ＋ 30
  - 球速 ← その年の最速
  - 変化量の合計 ← 防御率（上記）
- 本作の `playerCost()`（線形の重み付け平均 → 1〜15）は「逓増しない」点が違う。S の能力を持つ選手のコストが相対的に安く出やすい。

## 2. 特殊能力

### 2-1. しくみの分類

| 色 | 意味 | 例 |
|---|---|---|
| 金（超特殊能力） | 青特の上位。効果は青の 1.3〜2 倍程度 | 得点圏の上位版、2 ストライクの上位版 |
| 青 | プラス効果 | 状況別の打撃補正、打球傾向 |
| 赤 | マイナス効果 | 三振、併殺、一発、四球 |
| 青赤 | 長所と短所が両方 | 荒れ球、ゴロ/フライ傾向 |
| 緑 | **CPU が操作するときの行動傾向**（能力値は変えない） | 積極打法、慎重盗塁、テンポ |
| A〜G の段階式 | **D が効果なし**。A〜C がプラス、E〜G がマイナス | チャンス、対左、盗塁、ノビ… |

効果の**しくみは 6 種類**に分けられる（本作の設計にそのまま使える分類）:

1. **能力値への加算**（条件つき）: 「得点圏でミート +15・パワー +10」など。最も多い。
2. **打球の傾向**: ミート打ちでヒット性の打球が出やすい／強振で本塁打性が出やすい／ライナーが出やすい。
3. **見え方**: ストレートが実際より速く見える（ノビ）、変化が打者の近くで始まる（キレ）、対角線の球が速く見える。
4. **失投の確率**: 一発（真ん中に入りやすい）、逃げ球（入りにくい）。
5. **味方・相手全体への作用**: ムード（味方野手 ±5）、威圧感（相手投手を弱らせる）、捕手能力（投手のコントロール・スタミナ）。
6. **CPU の行動**（緑）。

### 2-4. 影響が大きいもの【推定。本作の「打撃のみ操作」に効く順】

1. **失投の確率（一発 / 逃げ球）** — ユーザーの長打の出やすさを直接決める。
2. **2 ストライク系（三振 / 粘り打ち / 奪三振）** — 打席ごとに毎回関わる。
3. **得点圏系（チャンス / 対ピンチ）** — 試合の山場で効き、ドラマを作る。
4. **左右の相性（対左投手 / 対左打者）** — 打席の半分近くで効く。
5. **ノビ・キレ** — 見え方（体感速度・変化の開始点）に効く。本作では着弾ゴースト表示の遅れ・最適タイミングのずれで再現できる。
6. **イニング系（立ち上がり / 尻上がり / スロースターター / 寸前）** — 継投のタイミングと試合の流れに効く。
7. **ムード・威圧感** — チーム全体への補正。少数でもオーダー全体に効く。

### 2-5. 本作の名称の点検

本作の `SKILLS`（js/data.js）は 35 種。多くは一般的な野球用語だが、次は扱いに注意する。

| 本作の名称 | 判断 | 理由・代案 |
|---|---|---|
| 怪物球威 | **改名推奨** | パワプロの金特の名前とまったく同じ。例: 「剛球」「豪腕」 |
| 天才打者 / 怪力 | 可（要確認） | 同名の能力はパワプロで確認できなかった。一般語 |
| チャンス◎ / 対左投手◎ など「◎」付き | 可 | 記号の付け方はパワプロ（○/◎ 表記）に近い。独自性を出すなら「チャンス+」や星表示も検討 |
| 初球○ / 粘り打ち / 広角打法 / 流し打ち / 重い球 / キレ◎ / ノビ◎ / クイック◎ | 可 | 野球の一般語 |
| 金特 / 青特 / 赤特 という呼び方 | UI では避ける | ファン用語として定着しているがパワプロ固有の呼び方。画面では「ゴールド能力」「プラス能力 / マイナス能力」など |

**採用してはいけない種類の名前**: 実在選手の愛称・決め台詞に由来する能力名（例: 球界の偉人の愛称、特定の守備コンビの通称、特定球場や球団の守護神の愛称、特定選手専用の英語名の能力）。シリーズにはこうした名前が多数あるが、本作では人物を想起させる名前を一切使わない。

## 3. 調子と疲労

### 3-1. 調子（試合ごと）

- **5 段階**: 絶好調・好調・普通・不調・絶不調【公式】。
- **打者の補正**（2022 以降）【検証】:

| 調子 | 弾道 | ミート | パワー |
|---|---|---|---|
| 絶好調 | +1 | +15 | +15 |
| 好調 | +0.5 | +10 | +10 |
| 普通 | 0 | 0 | 0 |
| 不調 | −0.5 | −10 | −10 |
| 絶不調 | −1 | −15 | −15 |

  - 「調子極端」は振れ幅が広がる（絶好調で +20）、「調子安定」は狭まる。弾道の増減は両者の影響を受けない【検証】。
  - 走力・守備・肩・捕球は調子の影響を受けない【検証】。
- **投手**: 球速・コントロール・変化量・スタミナが変わる【公式: 球速は調子で上下】。スタミナは上記 1-6。球速・制球の具体値は資料ごとに食い違い、**未確認**。
- **特能との関係**: 絶好調では赤特の多くが消え、絶不調では青特の多くが消える【公式＋検証】。
- **CPU への影響**: 2018 前後から、調子が CPU 操作の成績に目に見えて効くようになった、という報告【攻略: ペナント考察ブログ】。

### 3-2. 調子の決まり方・好不調の波（ペナント・マイライフ）

- 2020 から「**調子バイオリズム**」と「ランダム」を選べる【公式: 2020 開発ブログ】。
  - バイオリズム: **調子ごとに基本の継続日数**があり、**試合での活躍で継続日数が伸び縮みする**（活躍すると好調が続き、不振だと不調が続く）。
  - ランダム（既定）: 活躍が調子に反映されにくい。
- 「ノリノリ」（好調が続く期間）「スランプ」の頻度をペナント設定で変えられる【攻略】。
- 2024-2025 では、成績が極端に悪い選手が「成績不振で調整中」になり調子が上がりにくい。2 軍で休ませると回復しやすい【攻略】。
- 継続日数の具体値: **未確認**。

### 3-3. 試合中の「動揺」（投手）

- 打ち込まれると投手が**動揺**し、**スタミナに関係なく**能力が大きく下がる。目が回る演出で 2 段階あり、第 2 段階はその試合中は戻らない【攻略】。
- 効果は 球速低下・失投率上昇・変化量低下と言われるが、**数値は未確認**。
- スタミナの追加消費は段階 1/2/3 で 1 球あたり +9/+18/+27【検証】。
- 打たれ強さ（A〜G）で動揺のしやすさが変わる。短気（赤）は動揺中に制球 −10。

### 3-4. 疲労（ペナント）

- 打席数・投球数に応じて疲労がたまり、1 日ごとに一定量回復。試合に出ない日・移動日・2 軍は回復が多い【公式: 2018 開発ブログ】。
- **蓄積疲労**: 無理な起用でたまる赤い部分。長期休養でしか減らず、**シーズンをまたいで持ち越す**。**疲労の下限**として働く（蓄積 30% なら疲労は常に 30% 以上）【公式】。
- たまりやすさ: 捕手 ＞ 二塁・遊撃 ＞ 外野 ＞ 一塁・三塁 ＞ DH。フル出場は多め。サヨナラ負けの日は増える【公式＋攻略】。
- 年齢: 20 代はほぼ目立たない、30 歳前後で少し、34 歳以上は 1〜2 か月の連続出場で深刻【攻略】。
- 影響: 調子が上がりにくい・能力低下・ケガのしやすさ上昇【公式】。
- 救援投手は 3 連投を避けるのが定石【攻略】。

## 4. CPU の思考

公式の詳細仕様は非公開。以下は公式設定項目＋攻略・検証からの整理。

### 4-1. COM の強さ

- 打撃・走塁・投球・守備を**別々に設定**できる（各 5 段階）【公式: 説明書「オプション設定で COM の強さ」＋攻略】。
- **固定式**（よわい〜パワフル）と、**成績で変わる可変式**（イージー〜エキスパート）がある。可変式は、例えばノーマルなら「イージー〜ハード相当の間」で上下する【攻略: 回答者の説明。公式未確認】。
- 体感: 「つよい」と「パワフル」の差が大きい。打撃を「ふつう」より上げると本塁打が異常に増える、守備を上げると打率が下がる【攻略】。
- ペナントの自動試合には別に「**投打バランス 5 段階（既定 3）**」がある【公式: 2020】。

### 4-2. CPU 打者

- ストライクは確実に当て、**際どいボール球にはほとんど手を出さない**【攻略】。→ 人間相手よりボール球で釣りにくい。
- 緩急（チェンジアップ等）が CPU には特に効く【攻略】。
- 早いカウントから打つか（積極 / 慎重打法）、ミート打ちと強振のどちらを多用するかは**緑特で個人差**をつける【攻略】。

### 4-3. CPU 投手・配球

- **良い球種ほど多く投げる**: 緑特なしでストレートの割合が約 35%、ノビの良い投手ほど増える【検証】。
- 追い込んだら高めのボール球で空振りを狙う、同じ球を続けない、などは人間の攻略法としての記述で、CPU 側の配球ロジックは**未確認**。
- 2026 で「ストライク先行」「ボール先行」という配球傾向の能力が追加【公式: 2026 情報】。

### 4-4. CPU の走塁・盗塁

- **成功率が高い状況でしか盗塁しない**、捕手の肩・守備で企図が減る【攻略: 掲示板】。
- 積極盗塁がないと盗塁数が伸びない【攻略】。

### 4-5. CPU の守備シフト

- シフトの種類: 通常 / 前進 / 中間（併殺と本塁封殺）/ 長打警戒 / 外野前進 / ゲッツー / バント警戒 / 俊足警戒 など【攻略】。
- **打者のパワーで自動的にシフトを変える**例: 2024 の 1 打席勝負モードでは、打者のパワーが E 以下だと「内野は後ろ、外野は前」のポテンヒット警戒シフトになる【攻略: レジェンドバトル解説】。
- 自動切替の正確な条件: **未確認**。

### 4-6. CPU の采配

- オーダー: 「調子次第」「攻撃力重視」などの思考を選べる【攻略】。
- 継投: 疲労・スタミナを見て交代。2020 から**オープナー**（初回で交代）と**ショートスターター**（打者一巡で交代）を先発枠に設定可能【公式: 2020】。
- 代打は相手投手のタイプで選ぶ（ストレート主体ならパワー型、変化球主体ならミート型）のが定石【攻略】。CPU が同じ判断をするかは**未確認**。
- 采配の差がペナントの勝敗に与える影響は 1〜2 割（143 試合中 約 14 試合）という体感の見積もり【攻略】。
- 送りバント・敬遠・エンドランの CPU 判断条件: **未確認**。

## 9. 実装バックログ（システム）

前提: ユーザーは打撃のみ。CPU が両軍の投球、守備は自動。試合は即開始。
並びは**体験への影響の大きい順**。関数名は現行の js/engine.js・js/data.js に合わせた。名称はすべて独自のものにする。

### P1（打席の質と試合のテンポ）

1. **守備イニングの早送り（自動進行の要約表示）**
   ユーザーが打たない半イニングは、1 球ずつ演出せず結果だけを高速に流す設定（「全部見る / 要点だけ / 結果だけ」）。
   実装: engine.js に `simulateHalfInning(state, rng)`（`choosePitch` → `chooseSwing` → `resolvePitch` のループ、`state.half` が変わるまで）を追加し、`events` の配列を返す。game.js は得点・本塁打・三振などの要点だけをティッカーに出す。`simulateGame` と同じ部品を使う。

2. **失投（甘い球）の仕組み**
   CPU 投手の球が一定確率で真ん中付近に入り、変化も弱まる。打撃だけ操作のユーザーにとって「仕留める球」の源。
   実装: `pitchLocation()` 内で `pMistake = 0.04 + 0.08×(1 − k')`（`k' = 制球×調子/99`）。赤特「一発」×2、新しい青特「逃げ球」相当 ×0.5、動揺中 ×1.5、2 ストライク後 ×0.7。発生時は狙いを `(0, 0) ± 0.3` に置き換え、変化を `pitchBreak()` の ×0.5 にし、`loc.mistake = true` を返す。`swingProbabilities()` は `mistake` のとき `d −= 0.08`（見切りやすい）、hr ×1.3。目標: 失投 5〜9%/球。`TUNING.mistakeBase/mistakeK`。

3. **能力補正を加算式に統一（`effectiveStats`）**
   `effectiveStats(state, player, ctx) → { contact, power, trajectory, speed, velocity, control, breakMul }` を新設し、調子・特能を「+15」などの加算で反映。`meetCursor()`・`swingProbabilities()`・`pitchLocation()`・`chooseSwing()` は必ずこれを通す。
   `SKILL_FX` に `{ when, add: { contact: 15, power: 10 } }` の形を追加し、従来の重み倍率（`hits` など）は打球傾向系（パワーヒッター等）だけに残す。UI の能力発動表示（「ミート+15」）にも使う。

4. **調子をパワプロ並みの振れ幅に**
   `CONDITIONS` を加算に: 打者 絶好調 ミート・パワー +15・弾道 +1、好調 +10・+0.5、不調 −10・−0.5、絶不調 −15・−1。投手 絶好調 球速 +3km/h・制球 +10・スタミナ +25 … 絶不調 −3・−10・−15（投手の値は独自。パワプロの値は未確認のため）。
   弾道の小数は `lift` にそのまま足せる（`(trajectory − 2)×TUNING.trajLift`）。
   調整: 振れ幅が倍になるので、`tests/balance.mjs` で得点の分散が増えすぎないか確認（平均は対称な重みなら変わりにくい）。

5. **スタミナを「出来事で減る」方式に**
   `createGame()` で `stamina[id] = スタミナ×32 + (役割 starter ? 1500 : 0)` のゲージ単位に変更（UI は % 表示）。`pitchCore()` で 1 球ごとに `PITCH_COST[type]`（ストレート 27、変化球 33〜38、フォーク系 38）＋走者分（一塁 3、得点圏 7、満塁・二三塁 10）を引き、`resolveBattedBall()`・`applyHomeRun()` の後に被安打（30/45/60/80）・失点（40、同点 60、勝ち越し 80）を引く。先発の 7 回以降 +9/球。
   `fatigue()` は「残り 15% 未満」で発動するよう書き換え。CPU の交代基準も「残り 20%」に。
   目標: 先発 85〜110 球、両軍 270〜290 球。係数は独自値で調整（上の数字は出発点）。

6. **ユーザーチームの自動継投を CPU と同じ思考に**
   ユーザーは投手を操作しないので、ユーザー側の継投も CPU と同等であるべき。
   実装: `cpuManageMut()` に `state.autoSides`（例: `{ away: { pitching: true, pinch: false } }`）を追加し、守備側がユーザーでも `pitching: true` なら `cpuPitcherChange()` を呼ぶ。game.js の `autoManageUserPitcher()` は撤去してエンジンに一本化。代打・代走はユーザーの采配メニューに残す。

7. **継投の役割を 3 段に（先発 → セットアッパー → 抑え）**
   `pitchers` の並び（先発, 先発, 中継ぎ, 中継ぎ, 中継ぎ, 抑え）を使い、`pickRelief()` を拡張: 8 回・3 点差以内のリードでセットアッパー（中継ぎの中で最も能力の高い投手）、9 回で抑え、負けている試合は残りの中継ぎ。先発は「ゲージ残り 20% 未満」「7 回以降に連打（動揺）」で交代。
   `roleOf()` に `setup` を追加（data.js の `role` に `'setup'` を許可）。

8. **CPU の送りバント**
   NPB の犠打 1.1〜1.6 / 試合に近づける。
   実装: `chooseSwing()` で `{ mode: 'bunt' }` を返す条件: 無死一塁 / 無死一二塁、2 ストライク未満、打者が投手 or（ミート+パワー < 100）、または 7 回以降の同点〜1 点差で打順 7〜9 番。確率 0.5〜0.8。`TUNING.cpuBuntRate`。ユーザー打席には関係しないが、CPU 攻撃の得点パターンが現実的になる。

9. **死球と暴投**
   死球: `pitchLocation()` で打者側に大きく外れた球（`|x| > 2.0` かつ打者寄り、`y` がゾーン高さ）の一部を死球に。目標 0.6〜0.8 / 試合。`event.kind = 'hbp'`、`stats.hbp`。
   暴投: 走者ありで低めに大きく外れた変化球（`y > 2.0`）の 10〜15% を暴投に。目標 0.4〜0.5 / 試合。走者が 1 つ進む。

10. **盗塁死を現実の割合に**
    成功率 88% → 70% 前後に。`TUNING.stealPop`（握り替え）0.85 → 0.75、`stealDelivery` 1.35 → 1.25、CPU の企図条件 `cpuStealMin` 0.55 → 0.62（見込みの高いときだけ走る＝パワプロの CPU と同じ）。目標 盗塁 0.8〜1.2・盗塁死 0.35〜0.5 / 試合。

11. **段階式能力（A〜G）**
    data.js の `skills` に `'チャンスB'` のような段階つき名前を許可するか、`grades: { chance: 'B', vsLeft: 'C', steal: 'A', run: 'B', throw: 'C', injury: 'D', nobi: 'B', kire: 'C', pinch: 'B', toughness: 'C', quick: 'B' }` を追加。`GRADE_TABLE`（A +15/+10、B +8/+5、C +5/+2、D 0、E −5/−2、F −8/−5、G −15/−10 を独自値に）を `effectiveStats()` で参照。表示は能力画面に色つきの段階バッジ。

12. **CPU の守備シフト（ユーザーの打席で効く）**
    `autoFieldCore()` の守備位置を `DEFAULT_POSITIONS` × シフト倍率で決める: パワー 80 以上 → 長打警戒（外野 +8m、内野 +2m）、パワー 40 以下 → 前寄り（外野 −10m）、終盤 1 点を争う三塁走者あり・2 死未満 → 前進守備（内野 −4m）、無死一塁・弱打者 → バント警戒。打席開始時にシフト名を画面に表示（ユーザーへの情報になる）。`state.shift` に記録。

13. **ミートカーソルの大きさを曲線に＋2 ストライク補正**
    `meetCursor()`: `rx = cursorMin + (cursorMax − cursorMin) × (1 − (1 − c/99)^1.6)`（低い側で急に小さく、C 以上はゆるやか）。2 ストライクで「三振」相当は実効ミート −20、「粘り打ち」は +10（項目 3 の `effectiveStats` 経由）。

### P2（試合の厚みと CPU の個性）

14. **投手の動揺（連打で崩れる）**
    `state.rattle[pitcherId] = 0..2`。同一イニングで 3 連打 or 2 失点で段階 1、さらに 2 安打 or 失点で段階 2。効果: 制球 −15/−30、球速 −2/−4、失投率 ×1.5/×2、スタミナ追加消費。イニング終了で段階 1 は解除、段階 2 は試合中残る。打たれ強さ（段階式）で閾値 ±1。画面に投手の様子を表示すれば、ユーザーの「攻め時」が分かる。

15. **イニング系の投手能力**: 立ち上がり / 尻上がり / 寸前 / 乱調（独自名）。`fxActive()` に `when: 'firstInning' | 'late' | 'closeOut'` を追加し、`effectiveStats()` で 球速・制球・変化量を加算。

16. **相手全体・味方全体への能力**: 「ムード」（味方野手 ±5）、「威圧感」相当（相手投手 制球 −10・スタミナ消費増）、「捕手の配球」（投手の制球 +5〜10）。`effectiveStats()` で同じチームの出場選手を走査。

17. **緑特（CPU の性格）**: `cpuStyle: { swing: 'aggressive'|'patient', mode: 'meet'|'power', steal: 'aggressive'|'cautious', count: 'strikeFirst'|'ballFirst' }` を Player に追加。`chooseSwing()` のスイング率（積極 +8% / 慎重 −8%、初球は ×1.3 / ×0.7）、強振率、`cpuStealMut()` の企図率、`choosePitch()` のゾーン内率に反映。チームごとに打線の性格が変わり、配球を読む楽しみが出る。

18. **CPU 配球の「読み」**: 直前の 1〜2 球と打者の弱点（例: 三振が多い打者は低めの変化球、パワー型は内角高めを避ける）を `choosePitch()` の重みに反映。「同じ球を 3 球続けにくい」「速い球の後に遅い球」も。ノビの良い投手はストレートを多く（ストレート重み = 45 × (1 + ノビ段階×0.1)）。

19. **敬遠（CPU 守備時）**: 一塁が空き・得点圏・7 回以降の 1 点差以内・打者の（ミート+パワー）が次打者より 25 以上高い → 申告敬遠。`event.kind = 'walk', intentional: true`。ユーザーは「勝負を避けられた」演出が見られる。

20. **COM の強さを 4 系統で設定**: 設定画面に 打撃・走塁・投球・守備 の各 5 段階。投球 → `sigmaBase`・`cornerBase`・失投率、打撃 → `posNoiseContact`・`timingBase`、守備 → `fielderReact`・`errBase`、走塁 → `runMargin`・盗塁企図。`TUNING` を段階ごとに上書きするプリセット表 `COM_LEVELS` を engine.js に置く。現在の難易度（着弾表示・球の速さ）とは別軸。

21. **可変難易度（成績で強さが変わる）**: 直近 N 打席のユーザー成績（OPS 相当）で `COM_LEVELS` の投球段階を ±1 する設定。初心者でも打てて、上手い人には手強い。

22. **1 打席チャレンジ（○人抜き）モード**: 1 打席ずつ投手と勝負。勝ち（例: 安打・四球。長打はボーナス）でポイントと育成ポイント、負け（凡打・三振）でライフ −1、ライフ 3。10・25・40 人目でボーナス勝負。勝つほど自分の打者の能力が上がる。`createGame()` を 1 打席用の状態で使い、`pitchContact()` の結果で判定。新規 js/challenge.js。名前・登場人物は完全オリジナル。

23. **打撃スコアアタック**: 1 イニング or 10 打席で得点・ポイント（独自配点、例: 単打 1・二塁打 2・三塁打 3・本塁打 5・打点 1）を競う。個人ベストは localStorage（try/catch で囲む）。

### P3（シーズンと育成）

24. **「出番プレイ」型の短縮ペナント**: 4 チーム × 24〜30 試合。自チームの試合は「自分の打席すべて / 得点圏の打席だけ / 観戦」から選ぶ。他カードは `simulateGame()`。順位表・個人成績（打率・本塁打・打点・防御率）。新規 js/pennant.js、保存は localStorage。
25. **調子の波（バイオリズム）**: ペナントで、調子ごとの継続日数（例: 絶好調 2〜3、好調 3〜5、普通 4〜6、不調 3〜5、絶不調 2〜3 試合）と、活躍（安打・本塁打 / 被安打の少なさ）で継続日数を ±1。`state.condition` の初期値をペナント側から渡す（`createGame(..., { conditions })` は既にある）。
26. **疲労（ペナント）**: 野手は守備位置の負担（捕 1.5、二遊 1.2、外野 1.0、一三 0.9、DH 0.5）と出場で疲労、投手は球数と連投。疲労が多いと調子の抽選が悪い側へ寄り、能力 −5。救援の 3 連投禁止。
27. **成長と年齢**: シーズン終了時に年齢と成績で能力が上下（20 代前半 +、30 代半ば以降 −）。
28. **査定（総合力）の逓増化**: `playerCost()` を「各能力 v の査定 = v ≥ 70 で 1.5 倍、v ≥ 80 で 2 倍、v ≥ 90 で 2.5 倍」の逓増に。特能も段階式に対応。コスト上限つき大会（例: 上限 160 / 140 の 2 段階）を復活させる。
29. **名称の監査**: SKILLS の「怪物球威」を改名。今後追加する能力名は、人物の愛称・パワプロ固有の能力名と一致しないかを一覧で確認するテスト（tests/ に禁止語リスト）を追加。
